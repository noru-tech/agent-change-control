# ACC010: Agent approval without signed identity

**Under the opt-in `agent_review` policy, a change fails ACC010 when an agent approval of its current head is not backed by signed evidence.**

| | |
| --- | --- |
| Rule ID | `ACC010` |
| Policy key | `agent_approval_unsigned` |
| Default severity | `warning` (SARIF level `warning`) |
| Fails the default policy (`fail_on: medium`) | no |
| Specification | [AI Change Provenance §6.2](../../spec/ai-change-provenance.md#62-rules) |
| Conditions and fixtures | [docs/policy.md](../policy.md#exact-deterministic-conditions) |

## Why it matters

Under `agent_review` an agent approval only counts when a verified, signed review document backs
it (`agent_review.minimum_evidence` is `signed` and cannot be lowered in this version). A
declared agent reviewer is never enough. ACC010 flags agent approvals that the policy will not
count because their signing integration is missing or unverified.

## Outcomes

Every change gets exactly one outcome for this rule; only `fail` produces a finding. The
reason strings are the exact `reason` text `acc` writes into the assessment.

| Outcome | When | Reason text |
| --- | --- | --- |
| `fail` | `agent_review` applies and an agent approval of the current head has evidence below `agent_review.minimum_evidence`. | "An agent approval of the current head lacks the signed evidence the policy requires." |
| `pass` | Every agent approval of the current head carries signed evidence. | "Every agent approval of the current head carries signed evidence." |
| `unknown` | Never. | (none) |
| `not_applicable` | `agent_review` is off or out of label scope, or no agent approved the head. | "Agent approvals do not satisfy independence under this policy."<br>"Change carries none of the labels the policy scopes agent review to."<br>"No agent approved the current head." |

## Controls

[docs/control-mapping.md](../control-mapping.md) does not map ACC010 to a control objective. Its
reading table describes the expected response: "Do not count the approval; fix the reviewer's
signing integration." No control mapping is documented for this rule.

The mapping is a guide for control owners, not a compliance claim.

```console
    | jq -c '.assessments[] | select(.rule_id == "ACC010") | {status, reason}'
```


## How to fix

Have the reviewing agent's tooling sign a review document, verify it before the run, and pass it
with `--attestations PATH` plus `--verification PATH` or `--verified-by TEXT`
([signing](../signing.md), [authorship](../agent-authorship.md#signed-tier)). `acc` does not
verify signatures itself; it records who said they did.

## Recording a disposition

A finding is never deleted. To record a human decision about it, edit only the finding's
`disposition` in the manifest (`accepted`, `remediated` or `false_positive`, with `owner`,
`decided_at`, `rationale`, and `remediated_at` or an optional `expires_at`), then run
`acc check MANIFEST --as-of YYYY-MM-DD`. The date is required because the machine clock is never
read. A disposition suppresses the finding from the threshold decision on that date and leaves the
finding, its evidence and the summary intact; when `--policy` makes `acc check` re-evaluate the
manifest, dispositions carry over by finding ID. Exact rules: [policy and dispositions](../policy.md#recording-exceptions).

```json
{
  "status": "accepted",
  "owner": "security@example.com",
  "decided_at": "2026-09-01",
  "expires_at": "2026-09-30",
  "rationale": "Emergency patch; retrospective review completed.",
  "remediated_at": null
}
```

To change how the rule is enforced rather than record a one-off decision, set its severity or
disable it under `rules.agent_approval_unsigned` in a [policy](../policy.md). Disabling a rule removes its
finding and assessment; it never alters the recorded facts.
