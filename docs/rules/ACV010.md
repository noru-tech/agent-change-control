# ACV010: Schema violation

**An input is rejected when it does not conform to its JSON Schema.**

| | |
| --- | --- |
| Code | `ACV010` |
| Kind | Validation code: the input is rejected |
| Exit code | [3](../exit-codes.md#3-invalid-input-or-manifest) |
| Specification | [AI Change Provenance §6.6](../../spec/ai-change-provenance.md#66-validation) |
| Raised by | `src/normalize/mod.rs` (`ACV010 schema validation failed at …`), `src/normalize/schema_order.rs` (which violation is reported) |

## Why it matters

The schemas under [`schemas/`](../../schemas/) are closed: an unknown member, a missing required
member, a wrong type, or a value outside a closed vocabulary (an unknown actor kind, rule name or
evidence kind) is an error, not something to ignore. A misspelled policy key that was silently
dropped would change a verdict without anyone noticing. The message gives the JSON Pointer of the
violation (empty for the document root).

## Controls

No control mapping is documented for validation codes: they guard the integrity of the input, not
a change-control objective. Their effect on evidence is that a rejected export never yields a
clean result. See [control mapping](../control-mapping.md) for how the findings map.

## Failing example

Input: [`conformance/reject/human-clean--unknown-actor-kind.json`](../../conformance/reject/human-clean--unknown-actor-kind.json). An actor's `kind` is `robot`, outside the closed vocabulary. Other reject vectors cover an [unknown member](../../conformance/reject/human-clean--unknown-member.json), an [unknown policy rule](../../conformance/reject/human-clean--unknown-policy-rule.json) and a [lowered agent-review minimum](../../conformance/reject/agent-review-independent--lowered-agent-minimum.json).

```console
$ acc evaluate --conformance-json conformance/reject/human-clean--unknown-actor-kind.json
error: ACV010 schema validation failed at /actors/github:bob/kind (see https://github.com/noru-tech/agent-change-control/blob/main/docs/rules/ACV010.md)
{"codes":["ACV010"],"verdict":"invalid"}
$ echo $?
3
```

## Passing example

Input: [`conformance/accept/human-clean.json`](../../conformance/accept/human-clean.json). The same vector with `kind: human`.

```console
$ acc evaluate --conformance-json conformance/accept/human-clean.json | jq -c '{verdict, codes}'
{"verdict":"evaluated","codes":[]}
```

## How to fix

Correct the member at the reported pointer against the schema for that document
([events](../../schemas/change-events.schema.json), [manifest](../../schemas/manifest.schema.json),
[policy](../../schemas/policy.schema.json)). For policies, rule keys are the names listed in
[policy](../policy.md), not the `ACC` codes.

## Disposition

A validation code is not a finding and cannot carry a disposition. The input is rejected
outright: `acc` writes no manifest, findings or assessments for it and exits 3, because an
evaluator must not reach a verdict on facts that do not hold together
([spec §6.6](../../spec/ai-change-provenance.md#66-validation)). Fix the input, or the producer
that wrote it, and run again. If an export written by `acc export` or `acc scan` fails
validation, please [report it](https://github.com/noru-tech/agent-change-control/issues/new/choose).
