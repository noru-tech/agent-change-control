# ACV001: Approval after merge

**An input is rejected when an `approved` review is later than its change's merge.**

| | |
| --- | --- |
| Code | `ACV001` |
| Kind | Validation code: the input is rejected |
| Exit code | [3](../exit-codes.md#3-invalid-input-or-manifest) |
| Specification | [AI Change Provenance §6.6](../../spec/ai-change-provenance.md#66-validation) |
| Raised by | `src/normalize/mod.rs` (`ACV001 approval_after_merge`) |

## Why it matters

An approval given after the merge cannot have authorized what was merged. Counting it would turn a
missed review into a clean one, and silently dropping it would hide that the record is odd, so the
whole input is rejected and the producer has to decide what the record means.

## Controls

No control mapping is documented for validation codes: they guard the integrity of the input, not
a change-control objective. Their effect on evidence is that a rejected export never yields a
clean result. See [control mapping](../control-mapping.md) for how the findings map.

## Failing example

Input: [`tests/fixtures/approval-after-merge/events.json`](../../tests/fixtures/approval-after-merge/events.json). `bob` approves a day after the merge.

```console
$ acc evaluate tests/fixtures/approval-after-merge/events.json > /dev/null
error: ACV001 approval_after_merge (see https://github.com/noru-tech/agent-change-control/blob/main/docs/rules/ACV001.md)
$ echo $?
3
```

## Passing example

Input: [`tests/fixtures/approval-at-merge/events.json`](../../tests/fixtures/approval-at-merge/events.json). The approval carries exactly the merge time, which is allowed (at or before merge qualifies).

```console
$ acc evaluate tests/fixtures/approval-at-merge/events.json --format table > /dev/null
$ echo $?
0
```

## How to fix

Check the review and merge timestamps in the export. If the approval really came after the merge,
the change was merged without that approval: remove the review from the export (it cannot qualify)
and let ACC003 report the change; if a timestamp was mangled, re-collect it.

## Disposition

A validation code is not a finding and cannot carry a disposition. The input is rejected
outright: `acc` writes no manifest, findings or assessments for it and exits 3, because an
evaluator must not reach a verdict on facts that do not hold together
([spec §6.6](../../spec/ai-change-provenance.md#66-validation)). Fix the input, or the producer
that wrote it, and run again. If an export written by `acc export` or `acc scan` fails
validation, please [report it](https://github.com/noru-tech/agent-change-control/issues/new/choose).
