# ACV003: Unresolved or disallowed reference

**An input is rejected when a reference between facts does not resolve or is not allowed.**

| | |
| --- | --- |
| Code | `ACV003` |
| Kind | Validation code: the input is rejected |
| Exit code | [3](../exit-codes.md#3-invalid-input-or-manifest) |
| Specification | [AI Change Provenance §6.6](../../spec/ai-change-provenance.md#66-validation) |
| Raised by | `src/normalize/mod.rs` (every `ACV003 …` message) |

## Why it matters

Every rule reads identities through references: the change's author, the agent's operator, each
reviewer, the attestation behind `signed` evidence. A reference that points nowhere, or at the
wrong kind of actor, would let a rule compare identities that do not exist. The cases are: an
actor, operator or attestation missing from the registry; an operator that is not a human, or on a
change whose effective author is not an agent; agent review facts on a reviewer that is not an
agent; `signed` evidence that does not resolve to a signed attestation with a recorded verifier;
a malformed actor or attestation identifier.

## Controls

No control mapping is documented for validation codes: they guard the integrity of the input, not
a change-control objective. Their effect on evidence is that a rejected export never yields a
clean result. See [control mapping](../control-mapping.md) for how the findings map.

## Failing example

Input: [`conformance/reject/human-clean--unresolved-author.json`](../../conformance/reject/human-clean--unresolved-author.json). The change's author is `github:nobody`, which is not in the actor registry. Other reject vectors cover [signed evidence without a verifier](../../conformance/reject/claude-clean--signed-without-verifier.json) and [an operator on a human-authored change](../../conformance/reject/human-clean--operator-on-human-author.json).

```console
$ acc evaluate --conformance-json conformance/reject/human-clean--unresolved-author.json
error: ACV003 unresolved actor (see https://github.com/noru-tech/agent-change-control/blob/main/docs/rules/ACV003.md)
{"codes":["ACV003"],"verdict":"invalid"}
$ echo $?
3
```

## Passing example

Input: [`conformance/accept/human-clean.json`](../../conformance/accept/human-clean.json). The same vector with the author `github:alice`, who is in the registry.

```console
$ acc evaluate --conformance-json conformance/accept/human-clean.json | jq -c '{verdict, codes}'
{"verdict":"evaluated","codes":[]}
```

## How to fix

Make every referenced actor and attestation present in the export's registries, record operators
only for agent-authored changes and only as humans, and pass signed documents together with a
verifier (`--verification PATH` or `--verified-by TEXT`, see [signing](../signing.md)). The message
names which reference failed.

## Disposition

A validation code is not a finding and cannot carry a disposition. The input is rejected
outright: `acc` writes no manifest, findings or assessments for it and exits 3, because an
evaluator must not reach a verdict on facts that do not hold together
([spec §6.6](../../spec/ai-change-provenance.md#66-validation)). Fix the input, or the producer
that wrote it, and run again. If an export written by `acc export` or `acc scan` fails
validation, please [report it](https://github.com/noru-tech/agent-change-control/issues/new/choose).
