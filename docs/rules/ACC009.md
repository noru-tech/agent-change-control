# ACC009: Agent approval lacks required independence

**Under the opt-in `agent_review` policy, a change fails when every sufficiently evidenced agent approval is dependent on the author on a required dimension.**

| | |
| --- | --- |
| Rule ID | `ACC009` |
| Policy key | `agent_approval_not_independent` |
| Default severity | `high` (SARIF level `error`) |
| Fails the default policy (`fail_on: medium`) | yes |
| Specification | [AI Change Provenance §6.2](../../spec/ai-change-provenance.md#62-rules) |
| Conditions and fixtures | [docs/policy.md](../policy.md#exact-deterministic-conditions) |

## Why it matters

`agent_review` lets a signed agent approval stand in for a human one, but only when the reviewing
agent is independent of the change's author on every required dimension: `operator` (a different
human directs it), `provider` (another vendor), `identity` (a different verified signing identity)
and, when required, `instructions` (someone else wrote its instructions). ACC009 fails when the
only candidate approvals share one of these with the author, which would make the second pair of
eyes the first pair again.

## Outcomes

Every change gets exactly one outcome for this rule; only `fail` produces a finding. The
reason strings are the exact `reason` text `acc` writes into the assessment.

| Outcome | When | Reason text |
| --- | --- | --- |
| `fail` | `agent_review` applies, no independent human approval exists, at least one agent approval carries the required evidence, and every such approval is `dependent` on a required dimension. | "Every agent approval of the current head is dependent on a required dimension." |
| `pass` | An agent approval is independent on every required dimension. | "An agent approval of the current head is independent on every required dimension." |
| `unknown` | Some candidate approval is `unknown` on a required dimension and `dependent` on none. | "An agent approval of the current head is unknown on a required dimension and dependent on none." |
| `not_applicable` | `agent_review` is off or out of label scope, an independent human approval exists, or no agent approval carries the required evidence. | "Agent approvals do not satisfy independence under this policy."<br>"Change carries none of the labels the policy scopes agent review to."<br>"A human independent of the effective author approved the current head."<br>"No agent approval of the current head carries the evidence the policy requires." |

## Controls

[docs/control-mapping.md](../control-mapping.md) does not map ACC009 to a specific control
objective. Its reading table says "missed independence; the same response as for self-approval",
which is the segregation-of-duties concern mapped there for the evidence as a whole:

- ISO/IEC 27001:2022 Annex A: A.8.32 Change management; A.5.3 Segregation of duties; A.8.25 Secure development life cycle
- NIST SP 800-53 Rev. 5: CM-3 Configuration change control; CM-5 Access restrictions for change; AC-5 Separation of duties

Typical control response, from the same document: Missed independence; the same response as for self-approval.

The mapping is a guide for control owners, not a compliance claim.

## Failing example

Fixture: [`tests/fixtures/agent-review-dependent-operator/`](../../tests/fixtures/agent-review-dependent-operator/events.json). Under `agent_review`, the signed review agent's recorded operator is `alice`, who also operated the author agent.

```console
$ acc evaluate tests/fixtures/agent-review-dependent-operator/events.json --policy tests/fixtures/agent-review-dependent-operator/policy.yml --format json \
    | jq -c '.assessments[] | select(.rule_id == "ACC009") | {status, reason}'
{"status":"fail","reason":"Every agent approval of the current head is dependent on a required dimension."}
```

The manifest carries one `ACC009` finding (`acc-f5777cfd1de71ce1`, severity `high`) whose `explanation` is the reason above and whose `provenance` cites the API records it rests on.

## Passing example

Fixture: [`tests/fixtures/agent-review-independent/`](../../tests/fixtures/agent-review-independent/events.json). Under `agent_review`, the signed review agent is independent on operator, provider and identity.

```console

{"status":"pass","reason":"An agent approval of the current head is independent on every required dimension."}
```

## How to fix

- Use a reviewing agent that a different human operates, from another vendor, signing with its
  own identity; or get an independent human approval.
- See [agent reviewers](../policy.md#agent-reviewers) and the dimension table in
  [spec §6.5](../../spec/ai-change-provenance.md#65-independence-dimensions).

## Recording a disposition

A finding is never deleted. To record a human decision about it, edit only the finding's
`disposition` in the manifest (`accepted`, `remediated` or `false_positive`, with `owner`,
`decided_at`, `rationale`, and `remediated_at` or an optional `expires_at`), then run
`acc check MANIFEST --as-of YYYY-MM-DD`. The date is required because the machine clock is never
read. A disposition suppresses the finding from the threshold decision on that date and leaves the
finding, its evidence and the summary intact; when `--policy` makes `acc check` re-evaluate the
manifest, dispositions carry over by finding ID. Exact rules: [policy and dispositions](../policy.md#recording-exceptions).

```json
{
  "status": "accepted",
  "owner": "security@example.com",
  "decided_at": "2026-09-01",
  "expires_at": "2026-09-30",
  "rationale": "Emergency patch; retrospective review completed.",
  "remediated_at": null
}
```

To change how the rule is enforced rather than record a one-off decision, set its severity or
disable it under `rules.agent_approval_not_independent` in a [policy](../policy.md). Disabling a rule removes its
finding and assessment; it never alters the recorded facts.
