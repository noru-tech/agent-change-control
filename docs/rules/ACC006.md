# ACC006: Agent operator unknown

**An agent-written change fails ACC006 when no human operator is recorded for the agent, or the operator claim is weaker than the policy requires.**

| | |
| --- | --- |
| Rule ID | `ACC006` |
| Policy key | `unknown_agent_operator` |
| Default severity | `warning` (SARIF level `warning`) |
| Fails the default policy (`fail_on: medium`) | no |
| Specification | [AI Change Provenance §6.2](../../spec/ai-change-provenance.md#62-rules) |
| Conditions and fixtures | [docs/policy.md](../policy.md#exact-deterministic-conditions) |

## Why it matters

Without the human behind an agent's change, nobody can tell whether the reviewer was independent.
`acc` reports that gap instead of guessing: ACC006 fires, and ACC001, ACC002 and ACC003 become
`unknown`, never `pass`. It is a provenance gap, not a violation, which is why it is advisory
(`warning`, below the default `fail_on: medium`).

## Outcomes

Every change gets exactly one outcome for this rule; only `fail` produces a finding. The
reason strings are the exact `reason` text `acc` writes into the assessment.

| Outcome | When | Reason text |
| --- | --- | --- |
| `fail` | The effective author is an agent and no human operator is recorded, or the operator's evidence is below `minimum_authorship_evidence`. | "Agent authorship is recorded but its human operator is unknown."<br>"A human agent operator is recorded, but its evidence is below the policy minimum." |
| `pass` | A human operator is recorded with sufficient evidence. | "A human agent operator is recorded." |
| `unknown` | Never. | (none) |
| `not_applicable` | The effective author is not an agent. | "Effective author is not an agent." |

## Controls

[docs/control-mapping.md](../control-mapping.md) names ACC006 under ISO/IEC 42001:2023 ("explicit
record of the human operator of each agent-written change (ACC006 when missing)"):

- ISO/IEC 42001:2023: human oversight of AI systems and accountability for AI-assisted outputs

Typical control response, from the same document: Not a violation; a gap in provenance. Fix the declaration at the source (agent integration or PR template).

The mapping is a guide for control owners, not a compliance claim.

## Failing example

Fixture: [`tests/fixtures/agent-operator-unknown/`](../../tests/fixtures/agent-operator-unknown/events.json). Claude Code wrote the change and nothing records who directed it.

```console
$ acc evaluate tests/fixtures/agent-operator-unknown/events.json --format json \
    | jq -c '.assessments[] | select(.rule_id == "ACC006") | {status, reason}'
{"status":"fail","reason":"Agent authorship is recorded but its human operator is unknown."}
```

The manifest carries one `ACC006` finding (`acc-a77f6c869b9816b1`, severity `warning`) whose `explanation` is the reason above and whose `provenance` cites the API records it rests on.

## Passing example

Fixture: [`tests/fixtures/codex-clean/`](../../tests/fixtures/codex-clean/events.json). Codex wrote the change and the pull request's declaration names `alice` as its operator.

```console
$ acc evaluate tests/fixtures/codex-clean/events.json --format json \
    | jq -c '.assessments[] | select(.rule_id == "ACC006") | {status, reason}'
{"status":"pass","reason":"A human agent operator is recorded."}
```

## How to fix

Declare the operator where the agent opens the pull request, in the description:

````text
```agent-change-control
author: claude-code
operator: alice
```
````

Or supply a signed provenance document (`--attestations`, see [signing](../signing.md)). For
commits carrying a vendor `Co-Authored-By` trailer, the operator is derived only when one human
authored every commit ([authorship](../agent-authorship.md)). This finding does not fail the
default policy; raise its severity in a policy to make it blocking.

## Recording a disposition

A finding is never deleted. To record a human decision about it, edit only the finding's
`disposition` in the manifest (`accepted`, `remediated` or `false_positive`, with `owner`,
`decided_at`, `rationale`, and `remediated_at` or an optional `expires_at`), then run
`acc check MANIFEST --as-of YYYY-MM-DD`. The date is required because the machine clock is never
read. A disposition suppresses the finding from the threshold decision on that date and leaves the
finding, its evidence and the summary intact; when `--policy` makes `acc check` re-evaluate the
manifest, dispositions carry over by finding ID. Exact rules: [policy and dispositions](../policy.md#recording-exceptions).

```json
{
  "status": "accepted",
  "owner": "security@example.com",
  "decided_at": "2026-09-01",
  "expires_at": "2026-09-30",
  "rationale": "Emergency patch; retrospective review completed.",
  "remediated_at": null
}
```

To change how the rule is enforced rather than record a one-off decision, set its severity or
disable it under `rules.unknown_agent_operator` in a [policy](../policy.md). Disabling a rule removes its
finding and assessment; it never alters the recorded facts.
